# Contributing to NaN

Thank you for helping improve NaN. This repository is used as contest
infrastructure, so a small, well-explained change is more valuable than a large
collection of unreviewed snippets.

## Before opening a pull request

1. Search existing issues and pull requests for related work.
2. Open an issue for a new algorithm family, a structural change, or anything
   that changes generated notebook output substantially.
3. Confirm that you wrote the contribution or have permission to submit it.
   Do not copy code from another notebook, blog, book, or repository without a
   compatible license and explicit attribution.

English and Spanish are both welcome in discussions. Prefer English for new
public documentation and identifiers when it does not make the code less clear.
By submitting a contribution, you agree that it may be distributed under the
project's [MIT License](LICENSE).

## Where changes belong

- Update editable sources in a topic directory such as `grafos/`, `geometry/`,
  `strings/`, or `data_structures/`.
- In `Notebook_WF26` and `Notebook_PDA26`, folders ending in `_clean` are
  generated by `limpiar.py`. Do not edit those folders directly.
- Keep event-specific material in its event snapshot. Propose shared or
  canonical changes against the current `Notebook_WF26` snapshot first.
- Avoid committing compiler outputs, LaTeX intermediate files, or local editor
  metadata.

## Algorithm contribution checklist

Every new algorithm or meaningful algorithm change should document:

- the problem it solves;
- input assumptions and indexing conventions;
- time and memory complexity;
- important edge cases;
- the original author and source or derivation; and
- the upstream license when adapted from third-party material.

Prefer a small deterministic test. For subtle algorithms, add a stress test
that compares the optimized implementation against a simple brute-force oracle.

## Run the checks

From the repository root:

```bash
python3 -m compileall -q scripts Notebook_WF26 Notebook_PDA26 Notebook_WF "Notebook C++"
python3 scripts/validate_notebooks.py
g++ -std=gnu++20 -Wall -Wextra -Werror tests/smoke.cpp -o /tmp/nan-smoke
/tmp/nan-smoke
```

When changing the current generated notebook, also rebuild it:

```bash
cd Notebook_WF26
./gen.sh
```

Inspect the generated `_clean` files, `estufa.tex`, and PDF before committing.

## Pull request expectations

- Keep the title and description specific.
- Explain why the change is correct, not only what changed.
- Link the relevant issue when one exists.
- Include the commands used to validate the change.
- Expect a maintainer to request clearer provenance, additional edge cases, or
  a smaller change before merging.

All pull requests require human review. Automation may provide review notes or
tests, but it will not merge contributions on its own.
